> [!WARNING]
> **GitChrono is in alpha. Use at your own risk.** It runs real git commands on your repositories, so keep a pushed remote or a backup of anything you can't afford to lose.

## What's new in 0.6.1

0.6.0 was never published, so this covers everything since 0.5.0.

**Edit messages after the fact**
- **Edit message** in the commit details rewrites a commit's summary and description. For the latest commit that's an amend (staged changes stay staged); older commits on the current branch are reworded through a rebase. Merge commits, and commits with merges after them, are refused, and a commit a remote already has asks once more first, since the branch will need a force push
- **Rename stash** does the same for a stash, which keeps its place in the list
- Both can be undone with ⌘Z

**Stashes**
- Stashes stand out in the graph: a dashed box with a tray icon, a dashed line down to the commit they were made on, a dashed label and an italic message
- When applying a stash conflicts, the message now says which file and why (before, it ended at "failed:")
- Applying or popping a stash no longer gets in the way of your uncommitted changes. If they touch different files, the stash is applied on top and your changes stay. If they share a file, your changes are stashed first and a notice says where they went; ⌘Z puts everything back

**Pull and push**
- **Choose what Pull does** with the ▾ next to it: **Fetch all**, **Pull (fast-forward if possible)**, **Pull (fast-forward only)** or **Pull (rebase)**. The choice is remembered for every repository and also used by Pull in menus and the command palette. Until you pick one, Pull follows your git `pull.rebase` setting as before
- The toolbar's **Open** and **Fetch** buttons are gone: Fetch all is in the Pull menu, and opening a repository is on the Home tab, the command palette and ⌘O
- Rebase pulls work with uncommitted changes: they're set aside during the rebase and put back afterwards
- A fast-forward-only pull on diverged branches explains what to do instead of showing git's hints
- Pulling a branch with no upstream explains why instead of showing git's raw error, and offers the fix: **Track origin/main and pull** when the remote has a branch of the same name, or **Publish this branch** when it doesn't yet
- Pushing a branch with no upstream picks the remote the same way (your push default, then origin), and says so when there's no remote at all
- The Pull ↓ and Push ↑ counts are colored like the Home tab's: amber for behind, green for ahead

**Branches and tags in the graph**
- Right-clicking a branch or tag in the graph opens its menu (checkout, merge, rebase, delete, …), also inside the **+N** list when a commit has several. Before, nothing happened
- Tags can be pushed to any remote with **Push to origin** (one entry per remote). It never forces; if the remote has the tag on another commit, you get a clear message

**Tabs**
- Right-click a tab for **Close tab**, **Close other tabs** and **Close tabs to the right**
- Drag tabs to reorder them, like in a browser. Home stays first, and the order is remembered

**AI**
- Generated commit messages fill in the description too, not just the summary (the prompt steered models away from writing one)
- **Set up AI** leaves the toolbar once AI is set up, and comes back if you remove it. AI settings are always reachable from Settings → AI and the command palette

**Smaller things**
- When an update has downloaded, the footer shows a **Restart to update** button that relaunches into the new version. It asks first if you have unsaved work, like a commit message you're writing or a rebase in progress
- The changes panel has a clearer header ("N file changes on main"), a Path / Tree switch with icons, and outlined **Stage all changes** / **Unstage all changes** buttons
- Removing a repository from a project folder on the Home tab removes it from the list for good, instead of hiding it behind "N hidden · show". Nothing on disk changes
- Everything clickable shows the pointing-hand cursor, including the **×** on Home tab rows and the links in About

## Install

| Platform | File |
|---|---|
| macOS (Apple Silicon and Intel) | `GitChrono-0.6.1-macos-universal.dmg` |
| Windows 64-bit | `GitChrono-0.6.1-windows-x86_64.zip` (Git included) |
| Linux x86_64 / ARM64 | `GitChrono-0.6.1-linux-*.tar.gz` |

Already on 0.3.0 or newer? GitChrono offers this update itself. Step-by-step instructions are on [gitchrono.com/download](https://gitchrono.com/download/).

Requires `git` 2.40 or newer (included on Windows).
